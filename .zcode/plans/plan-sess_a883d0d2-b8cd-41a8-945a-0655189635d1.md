## Plan: a "code" specialist (classify + complete)

Add a new capability to the expert model, following the exact pattern of `vision.py`: a **specialist** with the shared trunk frozen, its own routed FFN expert, its own output head, and its own special tokens. It does two things:

1. **Classify** — feed a code snippet, get the language (python/java/javascript/php/ruby/go) off a class head at a trailing `<|cls|>` token in one forward pass. Fully tractable; mirrors vision exactly.
2. **Complete** — generate code continuation via the frozen trunk's LM head (next-token), routed through the code expert. Lower quality than a full LM, but it's the "completion" capability and it can't disturb chat/play.

### Dataset
CodeSearchNet (`code-search-net/code_search_net`), 6 configs: python/java/javascript/php/ruby/go. Field `whole_func_string` (function code). Mirror `vision.py._hf_images`: `load_dataset(repo, lang, split=split)` once per language, subsample to ~2k–4k each. Cap snippet length so docs fit the block.

### New file: `sodachat/code.py` (~340 lines, modeled on `vision.py`)
- **Constants**: `NAME = "code"`, special tokens `CODE = "<|code|>"`, `CLS = "<|cls|>"`, `LABELS = ["python","java","javascript","php","ruby","go"]`, `DEFAULT_PATH = _MODELS / "specialist-code.pt"`, repo id.
- **Loading/cleaning**: `_hf_snippets(lang, split, cap)` → list of cleaned code strings (strip, cap ~500 chars, drop degenerate). Config name = label.
- **Doc rendering**: `code_doc(snippet)` → `f"{CODE}\n{snippet}\n{CLS}"`. (No `<|end|>` — same as vision; one doc per sequence, class head at final `<|cls|>`.)
- **Tokenize/batch** (`_tokenize`, `_batch`, `_logits`, `_accuracy`): near-copies of vision's helpers — right-pad to max len, read class head at each doc's own `<|cls|>` position, route whole doc to the code expert.
- **`train(...)`**: `scaffold_specialist(base, name=NAME, special_tokens=[CODE,CLS], n_labels=len(LABELS), seed_from=GAME)` — seeded from GAME (token-grid-ish diets are closest). AdamW + `specialist_param_groups`, warmup→cosine, save on best val acc. Same scaffold/param-group/save-specialist machinery as vision.
- **`complete(lm, prefix, ...)`**: generation via the trunk LM head routed to the code expert. Use `model.generate_text(idx, task=code_task_id, ...)` (already in expert.py) — every token routed to the code expert, stop at `\n\n` or `END`. This is the completion path.
- **`classify(lm, snippet)`**: `lm.classify(NAME, code_doc(snippet))`.
- **`evaluate(...)`**: held-out accuracy per language + mixed.
- **`demo(...)`**: print a few snippets + predicted language.
- **`main()`**: `train | eval | demo | complete` subcommands, mirroring vision's argparse.

### `sodachat/agent.py` wiring (mirror the vision integration)
1. `_code_lm()` helper — like `_vision_lm()` (agent.py:288): ensure the expert is loaded; return it only if `NAME in specialists`, else None.
2. `_CODE_EXTS = (".py",".js",".java",".c",".cpp",".go",".rb",".php",".ts",".sh")` + extend `_find_image_path` → rename conceptually to a general `_find_file_path(exts)` OR add a parallel `_find_code_path`. Decision during impl: minimal change = add `_CODE_EXTS` and a `_find_code_path` that reuses the same quoted/bare regex. Route in `handle()` before chat, after image check.
3. `_cmd_code(arg)` — `/code <file>` classifies a dropped file's language; `/code <file> complete` runs completion. Like `_cmd_see`.
4. `_CODE_GOAL`-style follow-up: store last `seen_code` (language + name); answer plain-text "what language is it?" from it, like `_image_answer`.
5. Register commands `"code"`, `"lang"` → `_cmd_code` in `_COMMANDS`; add `/code <file>` to `_HELP`.
6. `/model` info already lists every `specialist-*.pt` generically (agent.py:646) — no change needed; the code specialist shows up automatically once trained.

### Out of scope / decisions made
- **Languages**: 6 (CodeSearchNet's configs). C/C++ would need a different/streaming dataset (codeparrot/github-code) — not worth the complexity; 6 well-sampled languages is plenty for a demo. If you want 8, that's a follow-up.
- **Completion quality**: will be weak (frozen trunk, ~14M params, function-level data). The plan is honest about this — classify is the reliable win, complete is the stretch.
- **No new dependencies** — `datasets` (already used) and stdlib only.
